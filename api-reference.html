API#

The pyfolio API is organized into various modules:

  • Tear Sheets: pyfolio.tears

  • Time Series Metrics: pyfolio.timeseries

  • Plotting Functions: pyfolio.plotting

  • Performance Attribution: pyfolio.perf_attrib

Timestamp and annualization conventions#

Pyfolio retains its historical date handling. Supply returns, positions and transactions with consistent timestamp and timezone conventions. Transaction volume and turnover group observations by normalized civil date; they do not look up exchange sessions. In an overnight market, two executions in one exchange session can therefore fall into different daily groups. Pyfolio does not infer the intended session or reconcile inconsistent labels.

The legacy tear-sheet APIs have no uniform calendar selector. They do not implement the current ML4T convention in which explicit calendar=None disables calendar handling. A continuous, 24/7 exchange schedule and calendar-free observation-based analysis are different contracts. Exchange-session assignment belongs upstream of these legacy APIs; retain execution timestamps when preparing data rather than treating an inferred daily label as the execution instant.

Standard daily performance statistics use 252 observations per year. Some standalone pyfolio.timeseries wrappers accept a period argument; standalone Empyrical functions also expose explicit annualization where supported. Those choices do not change every statistic or panel in a Pyfolio tear sheet. In particular, weekend observations, irregular timestamp spacing or an overnight exchange do not automatically select a different annualization scale. Use a consistent declared return frequency and verify the conventions of each calculation when a daily, 252-period report is unsuitable.

These conventions remain unchanged for compatibility. See the maintenance and migration guidance on the home page for the current ML4T libraries; evaluate session-aware successor workflows against their documented inputs and qualification scope.

Determines the upper and lower bounds of an n standard deviation cone of forecasted cumulative returns. Future cumulative mean and standard devation are computed by repeatedly sampling from the in-sample daily returns (i.e. bootstrap). This cone is non-parametric, meaning it does not assume that returns are normally distributed.

Parameters:

In-sample daily returns of the strategy, noncumulative. See full explanation in tears.create_full_tear_sheet.

num_daysint

Number of days to project the probability cone forward.

cone_stdint, float, or list of int/float

Number of standard devations to use in the boundaries of the cone. If multiple values are passed, cone bounds will be generated for each value.

starting_valueint or float

Starting value of the out of sample period.

num_samplesint

Number of samples to draw from the in-sample daily returns. Each sample will be an array with length num_days. A higher number of samples will generate a more accurate bootstrap cone.

random_seedint

Seed for the pseudorandom number generator used by the pandas sample method.

Returns:
pd.DataFrame

Contains upper and lower cone boundaries. Column names are strings corresponding to the number of standard devations above (positive) or below (negative) the projected mean cumulative returns.
